## Architecture (as of the extraction refactor)

- **`Recorder`** — the engine. Owns the pipeline, the
  `idle → recording → stopping → idle` state machine, and all timers. Uses
  GLib but **never Gtk**; reports out through `on_state` / `on_tick` /
  `on_error` / `on_finished`; raises `RecorderError(title, message)` for
  start-up failures so it never builds a dialog.
- **`RecorderWindow`** — thin view. Builds widgets, resolves path + format,
  calls `start()` / `stop()`, renders the callbacks.
- Platform split is one pair of constants near the top: `SOURCE_DESCRIPTION`
  and `CAPTURE_ELEMENT`, plus `DEVICE_LIST_HINT` / `INSTALL_HINT` for
  user-facing text. Linux uses `pulsesrc`; Windows uses
  `wasapi2src loopback=true ! audiorate`.

Adding a CLI, tray icon, or second GUI means reusing `Recorder` as-is. The
hard-won parts (EOS finalisation, timeout guards, teardown ordering) live
there, not in the window.

## Gotchas that will bite you

1. **Two GitHub accounts on this box.** `lrashhcad-hub` (HCAD work) is the
   active one and should stay that way. Before pushing *this* repo:
   `gh auth switch --user lrash`, and switch back afterwards. Credential
   pinning on the remote URL was not possible — the auto-mode classifier
   blocks reading/altering git credential-helper config.
2. **Private repo + MSYS2 git.** MSYS2's `git` has no credential helper and
   will prompt for a password GitHub no longer accepts. Clone with Git for
   Windows (browser auth) into `%USERPROFILE%`, then work from MSYS2.
3. **MSYS2 home ≠ Windows profile.** `expanduser("~")` there resolves to
   `C:\msys64\home\<user>`. The app uses `home_directory()` everywhere for
   this reason — do not reintroduce a bare `expanduser("~")`.
4. **`os.chmod` on Windows** cannot make a directory unwritable, which is why
   the engine suite skips that one check there.
5. **Stale copy:** `~/Downloads/system_audio_recorder.py` is a pre-port
   snapshot from earlier the same day. It predates the Windows work *and* the
   engine extraction. The repo is canonical — delete the loose copy or ignore
   it, but never edit it.

## Decisions worth remembering

- `low-latency` deliberately **not** set on `wasapi2src`: for a recorder,
  glitch-free capture beats a marginally faster stop.
- `audiorate` added to the Windows chain **up front** rather than held as a
  fallback: it is an inert passthrough when the source behaves, and fixes the
  WASAPI silence-gap risk when it does not.
- Merged and released before Windows verification at the owner's explicit
  instruction — hence the prominent beta labelling everywhere rather than a
  silent claim of parity.
- Pause/resume was considered and rejected as hard: pausing a live capture
  source creates timestamp gaps. That is a GStreamer problem, not an
  architecture one, and the refactor does not make it easier.
